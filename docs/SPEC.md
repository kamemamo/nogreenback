# NoGreenBack 仕様書（Windows 版を作るための資料）

Mac 版 2.3.12（コミット `d062fe7`）が何をどう動かしているかをまとめたものです。Windows 版はこの動きを再現することを目標にします。

- 使い方の説明は [README.md](../README.md) にあります。この文書は、README に書いていない作り方の決めごと（数値、順番、例外の扱い）を中心にまとめています。
- キーボードの配列データや AI への指示文など、長いものはここに写さず、元のソースファイルを示します。
- 「**Windows では**」と書いたところは、Mac の仕組みに頼っているため置き換えが要る部分です。置き換え方は提案です。決まったものは「17. Windows 版で決めたこと」にまとめています。
- 座標は、特に断りがなければ **左下原点**（Mac と Core Image の座標）で書いています。Windows（左上原点）では上下を読み替えてください。

## 1. 全体像

Web カメラの映像から人物だけを切り抜き、次の出し先に同時に出すアプリです。

| 出し先 | 内容 |
|---|---|
| プレビュー | 操作ウィンドウの左側。透明な部分は市松模様 |
| 全画面出力 | 合成した映像を、選んだ画面（プロジェクターなど）いっぱいに出す |
| ワイプ | 切り抜いた人物を、デスクトップの隅に透明な背景で常に手前に出す |
| Syphon | 他のアプリ（OBS など）へ透明付きの映像を送る。**Windows では Spout** |
| 画面録画 | 選んだ画面を MP4 に録画する（重ねた人物・手書きなども映る） |
| 字幕ファイル | 録画と同じ名前の .srt と、MP4 の中の字幕トラック |

これに加えて、手書き・ホワイトボード・キーボードの絵・指し棒・リアルタイム字幕・外部の音声・ATEM スイッチャーの操作があります。

### 処理の流れ

```
カメラ ─▶ 明るさ安定化 ─▶ 人物マスク ─▶ マスクの後処理 ─▶ 切り抜き ─▶ 左右反転
                                                                    │
背景（キャプチャー機器 / 画面）─────────────────────────────┐        │
                                                           ▼        ▼
                                          合成（背景・板・人物・キーボード・手書き・指し棒・字幕）
                                                           │
                         ┌─────────────┬───────────────────┼──────────────┐
                         ▼             ▼                   ▼              ▼
                     プレビュー     全画面出力           Spout 送出       （ワイプは切り抜きだけを使う）
```

- 映像の処理はカメラのコマが届くたびに 1 回行います。60 回/秒で描き続けることはせず、新しいコマができたときだけ各表示を描き直します（高解像度の画面でカクつかないように）。前の描き直しが終わっていないときは 1 回にまとめます。隠れている・閉じているウィンドウは描きません。
- **カメラがないとき**（つないでいない、0.5 秒以上コマが届かない）も、25 回/秒で人物なしの合成を続けます。背景・字幕・手書きなどを出し続けるためです。大きさは最後に受け取ったカメラの大きさ（最初は 1920×1080）を使います。この処理はカメラの処理と同じスレッドで走らせ、同時に動かないようにします。
- 処理中のフレームレートを 1 秒ごとに数えて、上部の右端に「25.0 fps」のように出します。

## 2. 操作ウィンドウ

- 大きさ 1240×760、最小 900×560。メインの画面の中央に出します。
- 上から「上部のボタン」「区切り線」「プレビュー（左）＋サイドバー（右）」の順に並べます。
- **操作ウィンドウを閉じたらアプリを終了します。** 終了する前に、画面を覆う透明なウィンドウ（手書き・ワイプ・全画面出力・字幕・キーボード・ホワイトボード・指し棒）を先に消し、ペン固定を外し、カーソルを戻します。透明なウィンドウだけが残ってクリックを受け止め続けるのを防ぐためです。
- 録画中に終了するときは、録画ファイルを閉じてから終了します（閉じないと再生できないファイルになります）。後片付けが 3 秒たっても終わらなければ、プロセスを強制終了します。
- メニュー: 「NoGreenBack を終了」（⌘Q）、「ヘルプ > ショートカットの一覧」（⌘/）。

### 上部のボタン（左から順に）

| ボタン | 種類 | 動き |

| 人物 | オン・オフ | 人物を出すかどうかの大もと。オフにすると、ワイプ・全画面・プレビュー・Spout のすべてから人物が消える |

| ワイプ | オン・オフ | デスクトップの隅に人物を重ねる |
| 字幕 | オン・オフ | 字幕の開始・停止 |
| 辞書のアイコン | ボタン | 字幕の設定（言語・AI・置き換え）を吹き出しで開く |
| （区切り） | | |
| 手書き | オン・オフ | 手書きの有効・無効 |
| ペン固定 | オン・オフ | キーを押さなくても描ける状態 |
| ホワイトボード | オン・オフ | 半透明の白い板 |
| 消去 | ボタン | 手書きを全部消す |
| キーボード | オン・オフ | キーボードの絵 |
| 指し棒 | オン・オフ | 指し棒 |
| ATEM の入力ボタンと「ミックス」 | | ATEM が USB でつながっている間だけ出す |
| （余白） | | ここから右は右寄せ |

### サイドバー（上から順に）

| 見出し | 項目 |
|---|---|
| カメラ | カメラ、品質、フレームレート、明るさ安定化、左右反転・上下反転・ストレートα（1 行に並べる） |
| 切り抜きの調整（開け閉めできる。開け閉めは保存） | ちらつき抑制、消失の保持、境界の締まり、境界ぼかし |
| 人物の位置と大きさ | 位置、大きさ、表示する画面 |
| 背景と全画面出力 | 背景映像、出す画面、映像の比率 |
| 手書き | 描くキー、色＋線を消す（1 行）、太さ、ボードの濃さ |
| キーボード | 配列、位置、大きさ |
| 録画 | 録画する画面、マイク＋メーター、映像＋音声（1 行）、長辺＋フレームレート（1 行）、形式、「1 時間で最大 約 ○ GB」 |
| 外部の音声 | 入力＋メーター、スピーカー、音量、声で下げる |
| ATEM スイッチャー | 状態の文字（USB で ATEM がつながっている間だけ出す） |

各項目の値の範囲と既定は「13. 設定の一覧」にまとめています。

### プレビュー

- 合成した映像を、縦横比を保って収まるように拡大縮小し、真ん中に置きます。映像の外の余白は黒です。
- 映像の中の透明な部分だけ市松模様を敷きます（16 px のます目、明るい灰 0.8 と暗い灰 0.55）。

## 3. 人物の切り抜き

### カメラ

- 一覧は、内蔵カメラ・外付けカメラ・iPhone のカメラ（Continuity Camera）です。起動時は一覧の先頭を開きます。
- 映像の形式は、**横長で幅 1920 以下のうち最も大きいもの**を選びます（同じ大きさなら Vision と相性のよい 420v 形式を優先）。縦横どちらも出せるカメラ（Osmo Pocket など）は、指定しないと縦長の枠に横長の映像を入れて送ってくるためです。
- フレームレートは 30 / 25 / 20 fps から選びます（既定 25）。カメラが対応する値のうち、選んだ値に最も近いものを設定します。カメラが飛び飛びの値（30/25/24 など）しか受け付けないときは、カメラが示す値をそのまま使います。
- カメラによっては撮影開始時にフレームレートを既定値に戻すので、フレームレートや形式が変わったら設定し直します。セッション開始後にもう一度設定します。
- **見張り:** 2 秒ごとに調べ、3 秒以上コマが届いていなければ、同じ機器（同じ ID）を探して開き直します。ATEM などのスイッチャーは、映像形式を変えたときやつないだ直後に USB の機器として一度消えて出直すことがあり、古いつながりのままだと一覧にあるのに映像が出なくなるためです。取り込みのエラーが起きたときも、次の見張りで開き直します。
- カメラがなくても映像の受け取り口は先に用意しておき、あとからカメラをつなげば映るようにします。カメラがないときは「カメラが見つかりません。カメラをつなぐと、自動で映ります。」と知らせます。
- コマは遅れたら捨てます（最新のコマだけ処理する）。

### 処理の順番

1. **明るさ安定化**（照明のフリッカーによる画面全体の明滅をならす）
   - カメラの画素を 64×36 点に間引いて CPU で平均の明るさを求めます（`0.114B + 0.587G + 0.299R`、sRGB の値をリニアに直すため 2.2 乗）。GPU で求めて読み戻すと毎コマ GPU を待つことになるためです。
   - 移動平均 `ref = ref × 0.9 + luma × 0.1`（約 10 コマで追従）を取り、`gain = clamp(ref / luma, 0.8, 1.25)` を求めます。
   - 強さ s（0〜1、既定 0.7）で `g = 1 + (gain − 1) × s` とし、RGB に g を掛けます。平均がほぼ 0 のときや s が 0 のときは何もしません。
2. **人物マスク**: Apple Vision の人物セグメンテーション（`VNGeneratePersonSegmentationRequest`、8 bit のマスク）。品質は Fast / Balanced / Accurate（既定 Balanced）。品質を変えたらマスクの履歴を捨てます。
   - **Windows では** 別のモデルが要ります（MediaPipe Selfie Segmentation、ONNX の人物セグメンテーションモデルを DirectML / Windows ML で動かす、など）。品質の 3 段階は、モデルや入力解像度の違いに当てはめます。
3. **ちらつき抑制**（時間方向の平滑化。強さ s は 0〜1、既定 0.6）
   - 前のコマのマスク prev と今のマスク cur から、画素ごとに `w = clamp((1 − s × 0.92) + |cur − prev| × 5, 0, 1)`、`out = prev + (cur − prev) × w`。
   - 動いた画素（差が 0.2 を超える）はすぐ追従し、止まっている画素ほど前のマスクを残します。
4. **消失の保持**（人物と判定された部分が急に消えたとき、ゆっくり消す。強さ h は 0〜1、既定 0.2）
   - `d = 0.02^h`、`out = max(out, prev − d)`。増える方向（人物が現れる）はすぐ反映し、減る方向だけ 1 コマあたり d までに抑えます。
   - h = 0.6 で 1 コマ約 0.1（30 fps で約 0.3 秒）、既定の 0.2 で約 0.46（約 0.07 秒）。
   - 3 と 4 の結果を次のコマの prev にします（2 枚のテクスチャを交互に使う）。
5. **境界の締まり**（強さ t は 0〜1、既定 0.3）: `g = 1 + t × 3` として、0.5 を中心にコントラストを上げます（`out = clamp(m × g + 0.5 × (1 − g))`）。半透明の縁が減ってくっきりします。
6. **境界ぼかし**（0〜6、既定 1.5）: マスクの解像度の上で、その値を σ にしたガウスぼかしをかけます（端は引き延ばしてからぼかし、元の大きさに切る）。
7. マスクをカメラの映像の大きさに拡大（線形補間）し、カメラの映像を、透明の上にマスクで合成します。
8. **左右反転**（既定オン）なら、切り抜いた映像を左右反転します。
9. 「人物」がオフなら、切り抜きを全部透明にします。

## 4. 合成

### 映像の大きさ（キャンバス）

- 高さはカメラの映像と同じです。
- 「映像の比率」が「出す画面に合わせる」（既定）なら、横幅を `高さ × 出す画面の横縦比` にします（偶数に丸める）。「カメラと同じ」ならカメラの大きさのままです。

### 人物の置き方

- 大きさの割合 p（「大きさ」0.15〜0.8、既定 0.35）を、カメラの映像の幅と高さの両方に掛けます（`pw = カメラの幅 × p`、`ph = カメラの高さ × p`）。
- 位置（右下・左下・右上・左上。既定は右下）に合わせて、キャンバスの隅にぴったり付けて置きます。

### 重ねる順番（奥から手前へ）

1. 黒
2. 背景映像（あるとき）。切らずに全部入るように縮めて真ん中に置く（比率が違うときの余りは黒）
3. ホワイトボードの板（白、不透明度＝「ボードの濃さ」。0.7 の白を黒に重ねると 178/255 になる）
4. 人物
5. キーボードの絵
6. 全画面出力の上に描いた手書きの線
7. 指し棒
8. 字幕

背景映像がないときは、1 と 2 を透明にします（プレビューでは市松模様、全画面出力では黒が見える）。

### Spout（Mac では Syphon）に送る映像

- **背景映像があるとき:** 上の合成と同じものを送ります。
- **背景映像がないとき:** 人物を**元の大きさのまま**（隅に縮めずに）送り、OBS 側で自由に配置できるようにします。板・キーボード・手書き・指し棒は入れず、字幕だけを下の中央に入れます。
- サーバー名は `NoGreenBack`、透明付きです。
- 「上下反転」（既定オン）と「ストレートα」（既定オフ＝プリマルチプライド）は、送る映像の向きと透明の形式を決めます。受信側で上下が逆になる・縁が黒や白になるときに切り替えるためのものです。Windows（Spout）では Direct3D のテクスチャが上から下に並ぶので、「上下反転」の既定はオフです（実機で、オフのとき受信側の向きが合うことを確かめました）。
- 色空間は sRGB。

## 5. 出し先ごとの決めごと

### 全画面出力

- 枠のないウィンドウで、選んだ画面全体（メニューバーや Dock の上も）を覆います。最初から画面の大きさで作ります（後から大きさを変えると描画が隅に寄ることがあったため）。
- 映像は縦横比を保って収まるように拡大し、余白は黒です（市松模様は敷かない）。
- Esc（そのウィンドウがキー入力を受けているとき）か ⌃⌥⌘ F で閉じます。開いたとき、このアプリが前面なら、すぐ Esc が効くようにキー入力を受けます。
- 「出す画面」の既定は、メイン以外の画面（なければメイン）です。
- **出していた画面が外れたら閉じます。** 残った画面に出し直すと、操作ウィンドウのある画面まで覆って操作できなくなるためです。
- 「出す画面」を変えたら作り直します。
- **全画面を外したら、ペン固定も外します**（そのままだと、操作ウィンドウのある画面まで手書きがクリックを受け止めて、マウスで操作できなくなるため）。

### ワイプ（デスクトップに重ねる人物）

- 枠なし・背景透明・クリックは後ろへ通す・アクティブにならないウィンドウです。
- 大きさは `幅 = 画面の幅 × 大きさ`、`高さ = 幅 × 9 / 16`。選んだ隅にぴったり付けます。
- 中の人物は、背景なしの切り抜きを幅に収まるように縮め、**下端を画面の下にそろえます**。
- Keynote や PowerPoint のスライドショーより手前に出します（Mac では画面を占有する表示と同じ最上位の層）。スライドショーを始めたときなど、同じ層に後から出たウィンドウに隠されないよう、**1 秒ごとに最前面へ戻します**。
- 出す条件: `ワイプ オン かつ 人物 オン かつ 全画面出力が同じ画面を覆っていない`。全画面出力が「表示する画面」と同じ画面に出ている間は、人物は出力の中に入るので、ワイプは隠します。
- 他のアプリの全画面表示（別のスペース）の上にも出ます。
- **Windows では** `WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOPMOST | WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` のようなウィンドウにし、定期的に最前面を取り直すことになると思います。

### 「表示する画面」「出す画面」「録画する画面」

- 画面は名前で覚えます。覚えた名前の画面がないときは、次の既定に戻ります。
  - 表示する画面: 主ディスプレイ（操作中の画面ではなく、一覧の最初）
  - 出す画面: メイン以外の画面
  - 録画する画面: 「表示する画面と同じ」
- 画面をつないだり外したりしたら、一覧・映像の比率・ワイプ・全画面出力・手書きのウィンドウ・背景の画面の取り込み・録画の対象をすべて作り直します。画面の数が減ったときは、ペン固定を外します。

## 6. 背景映像

- 選択肢は「なし（透明）」「画面: ○○」（この PC の画面）「キャプチャー機器やカメラ」「iPhone・iPad の画面: ○○」（Mac 版のみ）です。保存する ID は、画面なら `screen:画面の名前`、機器ならその機器の ID です。
- 背景は最新の 1 コマだけを持っておき、人物の処理のたびに使います。

### キャプチャー機器

- 1920×1080 で開きます。遅れたコマは捨てます。
- カメラと同じ見張りをします（2 秒ごとに調べ、3 秒以上コマがなければ同じ機器を開き直す）。

### iPhone・iPad の画面

- USB でつないだ iPhone・iPad の画面を、キャプチャー機器の 1 つとして背景に選べます（QuickTime と同じ仕組み）。iPhone の操作は iPhone 本体でします。
- 起動時に `kCMIOHardwarePropertyAllowScreenCaptureDevices` をオンにして、画面を取り込み機器として出してもらいます。機器は映像と音が一緒になった種類（muxed）で出てくるので、背景の一覧ではそれも探します。
- 一覧には「iPhone・iPad の画面: 機器の名前」と出します（同じ iPhone のカメラ＝連係カメラと見分けるため）。
- 1920×1080 にはせず、iPhone の画面の大きさのまま受け取ります。縦長の画面は、ほかの背景と同じく切らずに真ん中に置きます（余りは黒）。
- 画面が動かない間はコマが来ないことがあるので、「3 秒コマがなければ開き直す」見張りはしません。外れた・つながった知らせで止めたり開き直したりします。
- iPhone の音は、まだ録画に入れません。
- （2026-11-23 に追加。Mac 版のみ）**Windows 版**には、iPhone の画面を USB で取り込む仕組みがありません。Windows でするなら、AirPlay を受けるソフトで画面に映し、「この PC の画面」を背景にします。今は Windows 版では作りません。

### この PC の画面

- その画面を取り込みます。**このアプリ自身のウィンドウは映しません**（ワイプや全画面出力を映すと合わせ鏡になるため）。ただし、**手書きのウィンドウとホワイトボードのウィンドウだけは映します**（全画面出力に手書きが入るように）。
- 長辺 1920 まで、30 fps、マウスカーソル入り。
- 画面に変化がない間に来る中身のないコマは捨て、前のコマのままにします。
- 切り替えや停止のたびに番号を増やし、遅れて届いた古いコマや開始処理を捨てます。
- 初回は画面収録の許可が要ります。開けなかったときは知らせて「なし」に戻します。
- **Windows では** Windows.Graphics.Capture で画面を取り込みます。自分のウィンドウを外すには、外したいウィンドウに `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を付ける方法があります（ただしこれは録画にも効くので、録画に映したいウィンドウとの兼ね合いに注意。「9. 画面録画」を参照）。

## 7. ウィンドウの重なり順

手前ほど下の行です。Mac ではウィンドウの「層（レベル）」で決めています。

| 順 | ウィンドウ | 層 | クリック |
|---|---|---|---|
| 1 | ほかのアプリ（スライドショーも） | | |
| 2 | ホワイトボード | 最上位の層。ワイプのすぐ後ろに並べる | 通す |
| 3 | ワイプ | 最上位の層 | 通す |
| 4 | 字幕、キーボード | 最上位＋1 | 通す |
| 5 | 手書き | 最上位＋2 | 描くキーを押している間だけ受け取る |
| 6 | 指し棒 | 最上位＋3 | 通す |

- 同じ層のウィンドウは前後を取り合ってちらつくので、層を分けています（キーボードはワイプの 1 つ上）。
- 全画面出力は手書きより上の層ですが、全画面出力の上に描いた線は映像の中に入れるので、見た目は線が手前に出ます。

## 8. 手書き・ホワイトボード・キーボード・指し棒

### 手書き

- **画面ごとに**、画面全体を覆う透明なウィンドウを用意します（液晶タブレットのように別の画面として認識される機器でも描けるように）。画面の数が変わったら作り直します（描いた線は消える）。
- ウィンドウを実際に出しておくのは、描ける状態か、線が残っている画面だけです。何も描いていないのに画面と同じ大きさの透明なウィンドウを出しっぱなしにすると、画面 1 枚につき数十 MB の描画用メモリを使い続けるためです。
- **描くキー:** ⌥ Option（既定）/ ⌃ Control / ⌥⌘ Option+Command から選びます。押している修飾キーの組み合わせが**ちょうど**選んだものと同じときだけ描けます（Caps Lock・テンキー・fn は無視）。
  - キーの状態は 60 回/秒調べます。Mac では、ほかのアプリが前面でも、アクセシビリティの許可なしで読めます。
  - **Windows では** `GetAsyncKeyState` で同じように調べられます。ただし、**Alt を押して離すと多くのアプリでメニューバーにフォーカスが移る**ので、Alt を既定にすると「2 回押して全消し」でスライドのアプリの操作が乱れるおそれがあります。既定のキーは実機で決めてください（Ctrl が無難かもしれません）。
- 描ける間は、ウィンドウがマウスを受け取り、画面の縁に色の枠を出します（内側 2 の位置に太さ 4、ペンの色の 50%）。キーを離したら描きかけの線を確定し、クリックを後ろへ通します。
- **全部消す:**
  - 描くキーを素早く 2 回押す。「押してから 0.3 秒未満で離し、その間に線が増えていない」を 1 回とし、2 回の間が 0.4 秒未満なら消す。
  - 描ける間に右クリック。
  - 「消去」ボタン、⌃⌥⌘ C。
- **ペン固定**（⌃⌥⌘ D、上部の「ペン固定」）: キーを押さなくても描ける状態。手書きがオフなら、手書きもオンにします。
- 色: 赤（既定）・黄・青・緑・白・黒。⌃⌥⌘ K で次の色へ。
- 太さ: 2〜20（既定 5）。線の端とつなぎ目は丸く。
- 線を消す: 「消さない」（既定）・「3秒で消す」・「10秒で消す」。描き終えてからの秒数で、最後の 0.5 秒でフェードアウトします。消えかけているとき以外は描き直さないようにします（線が残っている間ずっと画面全体を描き直さないように）。
- 1 秒ごとに最前面へ戻します。
- **全画面出力を出している間は、描ける画面を全画面出力の画面と、録画している画面（録画中で、出す画面と違うとき）だけにします。** 操作ウィンドウのある画面などは、描くキーを押していてもペン固定中でも、マウスでふつうに操作できます。
- **全画面出力の画面の上に描いた線は、合成した映像の中にも入れます。** 全画面出力は映像を画面に収まるように拡大して真ん中に出しているので、その逆をたどってキャンバスの座標に直し、線を画像に描いて合成します（プレビューと、背景があるときは Spout にも入る）。録画では、全画面出力の画面の手書きのウィンドウを録画から外し、線が二重にならないようにします。
- 「手書き」をオフにすると、ペン固定とホワイトボードもオフにします。

### ホワイトボード

- 半透明の白い板です。オンにしたとき手書きがオフなら、手書きもオンにします。起動するたびにオフから始めます（保存しない）。
- **全画面出力を出していないとき:** 「表示する画面」全体に板のウィンドウを出します。ワイプのすぐ後ろに並べ、1 秒ごとに並べ直します。出すときのアニメーションはしません（一瞬、画面の縁だけ白くならないことがあったため）。
- **全画面出力を出しているとき:** 板のウィンドウは出さず、合成した映像の中（背景の上・人物の後ろ）に入れます。操作ウィンドウのある画面などには出ません。
- 板を出している画面を背景にしているときは、取り込んだ背景にもう板が入っているので、映像には重ねません（二重にしない）。
- 濃さ: 0.3〜0.95（既定 0.7）。
- 板のウィンドウは録画に映します。

### キーボードの絵

- 配列は JIS（日本語）と US（英語）。既定は、アプリの表示が英語なら US、それ以外は JIS。テンキー付き（テンキーは Windows の並び）。
- キーの名前は、Mac と Windows で違うところは両方書きます（白が Mac、水色が Windows）。
- キーの位置・幅・名前・shift で出る文字は [Sources/Keyboard.swift](../Sources/Keyboard.swift) の `makeKeys` にあります。1 キーの幅を 1 とした単位で、本体の幅 15、テンキーとの間 0.4、テンキーの幅 4、ファンクションキーの行の高さ 0.55。
- 色: 下地は黒に近い灰（0.08、不透明度 0.78）、キーは灰 0.22（0.95）、キーの縁は灰 0.45。
- 大きさ: 映像（または画面）の幅に対する割合 0.35〜0.95（既定 0.58）。
- 位置: 「人物の反対側」（既定）・下の中央・左下・右下・上の中央。余白は高さの 3%。
  - 「人物の反対側」は、人物と画面の端の**広い方のすき間の真ん中**に置きます。人物の体は枠の真ん中寄りにあるので、人物の枠を左右 20% ずつ狭めて体の端とみなします。入りきらなければ画面の端に寄せます。
- 合成した映像に入れます（手書きの線より下）。全画面出力が「表示する画面」を覆っていなければ、「表示する画面」にもウィンドウで出します（録画にも映す）。
- **押したキーを光らせる**（2026-11-24 に追加。Mac 版は済み。Windows 版も合わせる）:
  - キーボードを出している間だけ、ほかのアプリを使っている間も含めて、実際に押したキーを見ます。止めると光りも消します。
  - 押している間と、離してから 1 秒、そのキーをオレンジ（1, 0.58, 0.1）にし、縁を白く太くします。左右のある修飾キー（shift・command・option）は、押した側だけ光らせます。caps lock は押した瞬間だけ光らせます。
  - キーボードの上の帯に、押した組み合わせを大きな文字で出します。修飾キーは ⌃ control・⌥ option・⇧ shift・⌘ command の順で、ほかのキーとは「 + 」でつなぎます（例: 「⇧ shift + ⌘ command + 4」）。名前は絵のキーと同じ（JIS の @ のキーなら「@」）。修飾キーだけを押している間は、その修飾キーを出します。fn は矢印キーなどで自動で付くので出しません。押しっぱなしの繰り返しでは変えません。すべてのキーを離して 3 秒で消します。
  - 文字の帯は、位置が「上の中央」ならキーボードの下に、それ以外は上に足します（キーボード自体は動かさない）。字幕は帯の上に出ます。
  - Mac では、`CGEvent.tapCreate` の見るだけのタップ（listenOnly）で、keyDown・keyUp・flagsChanged を受け取ります。「入力監視」の許可が要ります。許可がなければ、キーボードを出すときに、この起動で一度だけ求めます（初回は Mac が許可の画面を出し、2 回目からはこちらから知らせる）。許可がなくても、キーボードの絵はいつもどおり出します。パスワードの欄に打っている間は、Mac がキーを渡さないので光りません。
  - **Windows では** `SetWindowsHookEx(WH_KEYBOARD_LL)` で同じことができます（許可は要りません）。パスワードの欄も隠れないので、パスワードを打つときはキーボードを消すよう README に書きます。

### 指し棒

- オンの間はマウスの位置を 60 回/秒調べ、マウスカーソルを隠して、棒の先の白い矢印をカーソルの代わりにします。特別な許可は要りません。
  - Mac では、操作ウィンドウでポップアップのメニューを選んだりボタンを押したりすると、macOS がカーソルを出してしまいます。メニューを閉じたときと、マウスのボタンを離したときに隠し直します（カーソルが出ているかを調べる関数は今の macOS で使えないので、いったん出してからすぐ隠す）。メニューを開いている間は、カーソルが見えます。
  - **Windows では** 拡大鏡の仕組み（`MagShowSystemCursor`）で、ほかのアプリの上でもカーソルを隠します。使えない PC では、システムのカーソルを透明な 32 ビットのカーソルに差し替え、カーソルを 1 画素動かして戻して、画面のカーソルの絵を読み直させます。強制終了などで隠したまま終わったときは、次に起動したときに戻します。2026-11-22 に変更しました。前は差し替えだけで隠していましたが、画面に出ているカーソルの絵が読み直されず、矢印が見えたままになる PC（240 Hz の画面と GPU のある PC）がありました。Mac 版は今のまま。
- 棒の長さは画面（映像）の高さの 45%。いつも矢印の右下から左上を指す形で、傾きは縦から、左端で 40 度、右端で 25 度（根元が右）。棒はいつも矢印の右下（0〜90 度）に出し、上や左には回しません。棒の根元が画面の内側（端から高さの 1% 内側）に収まるよう、下の辺と右の辺だけを見て傾きを決めます。
  - 下の辺にかからない、いちばん小さい傾き `lo = acos(clamp(先から内側の下の辺までの高さ ÷ 棒の長さ, 0, 1))`（寝かせるほど根元が上がり、90 度で横向き）
  - 右の辺にかからない、いちばん大きい傾き `hi = asin(clamp(先から内側の右の辺までの幅 ÷ 棒の長さ, 0, 1))`
  - `lo ≤ hi`（収まる向きがある）なら、好みの傾きを lo〜hi に収めた値。`lo > hi`（右下の隅のように収まる向きがない）なら、好みの傾きを hi〜lo に収めた値にして、棒の一部をそのまま画面の外に出します。隅に入るときも出るときも、傾きはなめらかにつながります。
  - 2026-11-21 に変更しました。前は 2 度ずつ回して収まる向きを探し、120 度（右上向き）まで回したり、それでもだめなら左側に回したりしていました。
- 傾きはマウスに少し遅れて変わります。1 回ごとに目標との差の 18% ずつ近づけ、差が 0.1 度未満になったら目標に合わせます。マウスのある画面が変わったら、すぐ目標の傾きにします。
- 絵: 太さが高さの 1.25% の黒い棒（灰 0.16）を、太さ 2.25% の半透明の白（不透明度 0.6）の縁の上に重ね、先に長さ 5.5%・半幅 2.2% の白い三角の矢印を付けます。矢印には黒い縁（灰 0.1、太さは高さの 0.3%、1 px 以上、角は丸く）を付けます。明るい画面では黒い棒と矢印の縁が、暗い画面では白い縁と白い矢印が見えます。矢印の先端がちょうどマウスの位置。影は付けません。棒は不透明度 0.6 で描き、下の文字が読めるようにします（白い縁と黒い棒が重なる所も濃くならないよう、棒全体を 1 枚の絵として透かす）。矢印は透かしません。（2026-11-21 に、茶色の棒と赤い矢印から変更。Mac 版・Windows 版とも同じ絵）（2026-11-22 に棒の不透明度 0.6 を追加。Mac 版・Windows 版とも）
- マウスが全画面出力の画面にあるときは、合成した映像の中に描きます（全画面出力の拡大の逆をたどって、映像の座標に直す）。それ以外の画面では、その画面を覆う透明なウィンドウに描きます（棒のまわりだけ描き直す）。
  - **Windows では** デスクトップの指し棒を、すべての画面を覆う透明なウィンドウに DirectComposition で置き、専用のスレッドで画面の合成の 1 回ごとにマウスの位置を読んで動かします（タイマーで動かすと、1 秒に 30〜60 回のばらばらな間隔になり、かくかくしたため）。全画面出力の上にもこのウィンドウを重ね、映像の中の指し棒はプレビューと Spout にだけ入れます（映像の中の指し棒はカメラのコマごとにしか動かないため）。Mac 版は今のまま（全画面出力の画面では映像の中に描く）。
- 録画に映します。

## 9. 画面録画

- 「録画する画面」を録画し、もう一度押すと止めて、ムービーフォルダに `NGB yyyy-MM-dd HH.mm.ss.mp4` で保存し、Finder でそのファイルを選んで見せます。**Windows では**「ビデオ」フォルダとエクスプローラー。（2026-11-23 に、名前の頭を「NoGreenBack」から短い「NGB」に変更。Mac 版・Windows 版とも）
- **映すもの:** ワイプ、手書き（全画面出力の画面のものは除く）、全画面出力、ホワイトボード、キーボード、指し棒。**映さないもの:** 操作ウィンドウ、録画停止ボタン、デスクトップの字幕（字幕は .srt と字幕トラックで残す）。録画中に出し入れしたウィンドウも、この決まりで映す・映さないを更新します。
  - **Windows では** 映さないウィンドウ（操作ウィンドウ・録画停止ボタン・デスクトップの字幕）に `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を付けるのがいちばん素直です。ただしこの指定は背景の画面の取り込みにも効くので、背景用の取り込みとの組み合わせを確かめてください。
- **録画停止ボタン:** 録画している画面の右上（メニューバーの下、右から 16・上から 12）に、「■ 録画停止」と経過時間の小さなパネルを出します。録画に映さず、ドラッグで動かせます。画面が 2 つ以上あっても、どの画面を録画しているかひと目でわかるようにするためです。録画を始める前に出しておき、録画の対象から外します。
- **操作ウィンドウと同じ画面を録画するとき**（モニターが 1 台のときなど）は、録画を始めたら操作ウィンドウを Dock にしまい（**Windows では**最小化）、止めたら元に戻して前面にします。
- 経過時間は「0:00」、1 時間を超えたら「1:00:00」の形。
- 押した時点ではボタンの色を変えず、録画が実際に始まった・止まったときに変えます。処理中はボタンを押せなくします。止めたあとファイルを仕上げる間は「保存中…」と出します。
- **落ちても消えない録画:** 録画中は 2 秒ごとに区切って .mov に書き込み（2 秒ごとにキーフレーム）、止めたら**再圧縮せずに** .mp4 へ詰め替えて .mov を消します。詰め替えに失敗したら .mov を残します。アプリが落ちたり電源が切れたりしても、.mov はそこまで再生できます。**Windows では** 断片化した MP4（fragmented MP4）で書き、止めたら通常の MP4 にする、などで同じ考え方を実現できます。
- **画質:**

  | 項目 | 選べる値 | 既定 |
  |---|---|---|
  | 映像 | 4 / 6 / 8 / 10 / 12 / 16 / 20 / 30 / 40 Mbps（平均ビットレート） | 8 |
  | 長辺 | 1280 / 1920 / 2560 / 3840 / 縮めない | 1920 |
  | フレームレート | 24 / 25 / 30 / 50 / 60 fps（最大値） | 30 |
  | 形式 | H.264 / HEVC | H.264 |
  | 音声 | 64 / 96 / 128 / 192 / 256 kbps（AAC・48 kHz・モノラル） | 128 |

  - 長辺は、画面の**実際の画素数**（高 DPI の画面では論理ピクセル × 倍率）を縦横比を保って縮め、偶数にそろえます。画面のほうが小さければ画面のまま。
  - 画面が動かない間はコマ数が減ります。
  - 「1 時間で最大 約 ○ GB」は `(映像 Mbps × 1000 + 音声 kbps) × 3600 / 8 / 1,000,000`。
  - 圧縮はハードウェアのエンコーダーを使います。
- 画面に変化がなく 1 コマも書けなかったときは保存せず、「画面に変化がなかったため、録画は保存されませんでした。」と知らせます。
- マイクを選んでいたのに音が 1 つも書けなかったときは、「マイクの音が届いていなかったため、録画には音が入っていません。」と知らせます。

### 録画の音声

- 1 本のモノラル（48 kHz、AAC）です。
- **マイク**は 48 kHz・モノラル・32 bit 浮動小数にそろえてから書きます（Bluetooth は 16/24 kHz、仮想デバイスはステレオなど、マイクごとに形式が違うため）。
- **時刻の付け直し:** Bluetooth のマイクは音の届く時刻が不規則で、届いた時刻のまま書くとすき間が無音になって途切れます。最初の時刻を基準に、サンプル数から時刻を付け直して隙間なく並べます。0.25 秒以上ずれたら基準を取り直します。映像が始まる前の音は捨てます。
- **外部の音声を混ぜる:** マイクがあれば、外部の音をためておき、マイクの音に `外部 × 下げる倍率 × 音量` を足します（−1〜1 に収める）。マイクが「なし」なら外部の音だけを `× 音量` で録ります。外部の機器とマイクが同じ機器なら混ぜません（二重になるため）。たまりすぎたら古いほうを捨てて遅れないようにします。
- **声で下げる:** マイクの音の大きさ（RMS）が −36 dBFS を超えたら、外部の音を「下げる倍率」まで 0.05 秒で下げ、話し終わって 0.6 秒たったら 0.5 秒かけて戻します。倍率は 下げない（1）/ 少し −6 dB（0.5）/ 半分くらい −12 dB（0.25、既定）/ 大きく −20 dB（0.1）。スピーカーに出す音は下げません。
- 録画中に「音量」を動かしたら、録画に入る音にも反映します。
- 録画中は、メーター用にマイクを別に開きません（同じ Bluetooth マイクを 2 か所から開くと途切れるため）。メーターは録画側のレベルを使います。

## 10. 字幕

### 認識

- マイクは「録画」の「マイク」で選んでいるものを使います。
- 言語は日本語か英語（既定は、アプリの表示が英語なら英語、それ以外は日本語）。
- 端末の中だけで認識し、音声はネットに送りません。Mac では、macOS 26 以降は新しい音声認識（SpeechAnalyzer）、それより前は従来の音声認識を使います。
  - **Windows では** 候補として、Windows の音声認識（Windows.Media.SpeechRecognition）、Whisper を端末で動かす、Azure の音声サービス（ネットに送る）があります。「音声をネットに送らない」を守るかどうかは決める必要があります。
- 「字幕の置き換え」の正しい表記の語を、認識のヒントとして渡します。
- 話している途中の文字も次々に出します。文が確定したら、確定した文として扱います（字幕ファイルと AI の校正に使う）。
- 4 秒以上話さなかったら、前の文は消して新しく始めます。画面に出す文字は、確定した文をつないだもの（最後の 200 文字まで）に、話している途中の文字を足したものです。
- 従来の認識では、ひと区切りごとに認識を作り直して長く話し続けても止まらないようにし、失敗が 5 回続いたら止めて知らせます。

### 置き換え

- 1 行に「間違い → 正しい」と書きます。区切りは `→`、`->`、`=`、`＝` のどれでもよい。
- 長い「間違い」から先に置き換えます。画面の字幕・字幕トラック・字幕ファイルのすべてに効きます。
- 書いた内容は 0.8 秒待ってから自動で保存し、すぐ認識に使います。「保存…」でテキストファイルに書き出し、「読み込む…」で入れ替えます。
- 設定の吹き出しには、認識する言語、AI で直す（使えないときは理由を添えて選べなくする）、置き換えの欄、行数があります。

### AI で聞き間違いを直す

- 確定した文を、端末の中の AI（Apple Intelligence）で読み直し、誤変換・同音異義語・専門用語の表記だけを直します。既定はオン（使えない環境では何もしない）。
- AI には、正しい表記の語の一覧と、直前に確定した 2 文を一緒に渡します。指示文は [Sources/SubtitleRefiner.swift](../Sources/SubtitleRefiner.swift) にあります（日本語と英語）。温度は 0。
- 次の場合は直しを使わず、聞き取ったままにします。
  - 長さが元の 0.6 倍未満か、1.4 倍＋4 文字を超える（言い換えや説明を返したとみなす）
  - 改行が入っている
  - 元の文の「○○キー」（カタカナ＋キー）や英字・数字の並びが、直した文に残っていない（操作の説明でいちばん大事なところなので、AI より聞き取ったままを信じる）
- 「直す文:」などの前置きや、かぎかっこ・引用符で囲んで返したときは外します。
- 同時に直すのは 1 文だけ。直している間に来た文は、いちばん新しい 1 つだけ待たせます（古いものは飛ばす）。
- 直せたら、画面に出ている字幕と、録画中ならその文の字幕ファイルの文を差し替えます（直した組を最新 10 件覚えておき、画面の文字に当てる）。
- **Windows では** Copilot+ PC の端末内の言語モデル（Phi Silica など）や、端末で動く小さな言語モデルが候補です。使えない PC では、この機能を出さないか選べなくします。

### 出し方

- **行の分け方:** かな・漢字を含む文は 1 行 26 文字で区切ります。それ以外（英語など）は単語の切れ目で折り返して 1 行 42 文字まで。出すのは**最後の 2 行**だけです。
- **映像の中の字幕:** 文字の大きさは映像の高さの 5%、太字、白、影（ぼかしは文字の大きさの 15%）、行間 15%。黒 55% の帯の上に描き、帯の余白は文字の大きさの 40%。帯が映像の幅（左右の余白 3% を除く）に入りきらなければ、文字を小さくします。
- **位置:** 人物を出しているときは、人物にかからないよう**キーボードと同じ「広い方のすき間の真ん中」**に、そうでなければ中央に置きます。入りきらなければ画面の端に寄せます。高さは下から 6%、キーボードが下半分にあればその上（余白 3%）。
- **デスクトップの字幕:** 「表示する画面」の下に、ウィンドウで出します（文字の大きさは画面の高さの 4%、角の丸い黒 55% の帯）。全画面出力が「表示する画面」を覆っているときは出しません。録画には映しません。
- 4 秒話さないと消します。

### 録画したときの字幕

- 録画中に確定した文を、話し始めた時刻と確定した時刻と一緒に残します（話し始めの時刻がわからないときは、確定の 2 秒前）。
- 止めたら次の 2 つを作ります。
  - 動画の中の字幕トラック（QuickTime Player の「表示 > 字幕」で出し入れできる）
  - 録画と同じ名前の .srt
- **画面と同じ形に分ける:** 1 つの文が 2 行を超えるときは 2 行ずつに区切り、文字数に応じて時間を分けて順に出します。表示時間は最低 0.3 秒、1 つの文の長さは最低 0.5 秒とみなします。
- .srt の時刻は `HH:MM:SS,mmm`。

## 11. 外部の音声とマイク

### マイク

- 選択肢は「なし」「システムの設定に合わせる」（その時点の既定の入力の名前を添える）と、つながっているマイクです。既定は「システムの設定に合わせる」。
- 選んだマイクが外れていたら「システムの設定に合わせる」に戻します。システムの既定の入力が変わったら、表示とメーターを合わせます。
- マイクを選んでいる間は、録画していなくてもメーターのためにマイクを開きます。メーターは「話したときに緑〜黄色まで振れればちょうどよい」くらいの目盛りです。

### 外部の音声

- 「入力」で取り込む機器を選ぶと（「使わない」で止める）、アプリが裏にあっても取り込み続けます。48 kHz・モノラルにそろえます。
- 「スピーカー」: 出さない / システムの出力 / 機器の名前。取り込んだ音をそのまま出します（LadioCast のような使い方）。
- 「音量」（0〜1、既定 1）は、スピーカーに出す音と録画に入る音の両方に効きます。
- メーターで入力レベルを出します。

## 12. ATEM スイッチャー

- Blackmagic Design の USB 機器（メーカー番号 `0x1EDB`）のうち、名前に「ATEM」が入っているものがつながったら、自動でつなぎます（同じメーカーのキャプチャー機器には反応しない）。外れたら切ります。起動時に挿さっていれば最初からつなぎます。
- USB で操作するには、Blackmagic の ATEM Software Control に入っている SDK（`BMDSwitcherAPI`）を使います。入っていないときは、サイドバーに「ATEM Software Control を入れると、USB で操作できます」と出します。SDK の窓口は [Sources/ATEMSDK](../Sources/ATEMSDK)（C++）です。**Windows でも** 同じ SDK（COM）が使えます。
- つながったら、上部に入力ボタン（入力の名前）と「ミックス」のチェックを出し、サイドバーに状態（「つながりました（USB）」など）を出します。
- ボタンを押すと、その入力を本番（PGM）に出します。「ミックス」がオンなら ATEM で設定している切り替え効果で移り（長さ 0.5 秒＝映像のフレームレートから求めたコマ数）、オフならすぐ切り替えます（カット）。「ミックス」は保存します。
- ATEM 本体などで切り替えたときも、ボタンの表示を追従させます。
- ATEM.swift には、SDK がないときに LAN（UDP 9910）で直接話す実装も残っています（今は USB でつながっているときだけ使う作り）。

## 17. Windows 版で決めたこと

2026-11-19 に決めました。理由も残しておきます。

1. **言語と UI: C#（.NET 10）＋ WPF**
   - 透明でクリックを通す常駐ウィンドウ（ワイプ・手書き・ホワイトボード・字幕・キーボード・指し棒）が多いので、Win32 の指定（`WS_EX_LAYERED` など）を付けやすい WPF にする。WinUI 3 は透明なウィンドウや多数のウィンドウの扱いが手間なので使わない。
   - 映像（プレビュー・全画面出力・Spout）は WPF に描かせず、Direct3D 11 で描く（C# からは Vortice.Windows などを使う）。
   - ATEM の SDK は Windows では COM なので、C# から直接使う（2026-11-19 に決め直し。インターフェースは SDK の `BMDSwitcherAPI.idl` のとおりに宣言する。Mac 版の `Sources/ATEMSDK` のような C++ の窓口は挟まない）。
   - Spout は、送り手の決まり（共有メモリの名前の一覧・送り手の情報・共有テクスチャ・アクセス用のミューテックス）が簡単なので、SDK を使わず C# だけで送る（2026-11-19 に決め直し。ビルドに C++ の道具が要らないようにするため）。
2. **人物の切り抜き: ONNX Runtime ＋ DirectML（GPU がなければ CPU）**
   - 品質の 3 段階: Fast は MediaPipe Selfie Segmentation（landscape、入力 256x144）、Balanced は MODNet（入力 512x288）、Accurate は MODNet（入力 672x384）。GPU（DirectML）が使えない PC では、どの品質でも Fast を CPU で動かす。
   - 試作で MediaPipe・PP-HumanSeg・MODNet（3 つの大きさ）を比べて決めた（2026-11-19）。縁の質はどれも使える出来だった。速さは、GPU ならどれも 1 コマ 20 ms 以内で 30 fps に収まり、CPU で 30 fps に間に合うのは MediaPipe と PP-HumanSeg だけだった。PP-HumanSeg は正方形の入力（192x192）で横長の映像に合わず、MediaPipe より CPU で遅いので使わない。測った数字は `windows/README.md` にある。
   - モデルは同梱せず、`windows/models/download.ps1` で版を固定して取ってくる（どちらも Apache-2.0）。モデルは差し替えられる作りにする。
   - Robust Video Matting は GPL-3.0 なので同梱しない。Windows ML への移行（Windows 11 24H2 以降が要る）は後で考える。
   - 3 章のマスクの後処理（ちらつき抑制など）はモデルによらず同じものを使う。
3. **字幕の認識: 端末の中だけで行う（Whisper。whisper.cpp を Whisper.net から使う）**
   - 「音声をネットに送らない」を Windows でも守る。Windows の音声認識（文章の書き取り）はオンライン音声認識を使うので採らない。
   - 話している途中の文字は、少し前からの音声を約 1 秒ごとに読み直して出す。
   - 「字幕の置き換え」の正しい表記は、Whisper の最初に渡す文章（initial prompt）に入れて、認識のヒントにする。
   - モデルは同梱せず、初めて字幕をオンにしたときにダウンロードする。GPU がない PC では小さいモデルを使う。
   - 使うモデル（2026-11-19 に速さを測って決めた）: GPU（Vulkan）が使える PC は large-v3-turbo（q5_0、574 MB。1 回の認識 約 0.5〜0.65 秒）、使えない PC は small（q5_1、190 MB。CPU で約 2.2 秒）。large-v3-turbo は CPU では 1 回 約 10 秒かかり、字幕に使えない。測った数字は `windows/README.md` にある。
   - 話している区間は音の大きさで見つけ、話している間は約 1 秒ごとに区間を読み直して途中の文字を出し、0.7 秒黙ったら（または 20 秒続いたら）文を確定する。無音のときに Whisper が出しがちな決まり文句（「ご視聴ありがとうございました」など）は字幕にしない。
4. **AI での校正: 初版では入れない**
   - 置き換え辞書と Whisper のヒントで補う。2 版目で、GPU がある PC だけ端末内の小さな言語モデル（llama.cpp / ONNX Runtime GenAI）で足す。
   - 校正の入口と、AI の直しを使わない判定（10 章の長さ・改行・「○○キー」の条件）は先に作っておき、あとからモデルをつなげるようにする。使えない PC では選べなくする。
5. **ショートカットと描くキー**
   - 全体のショートカットは **Ctrl＋Alt＋Shift＋キー**（キーは 14 章と同じ）。ほかのアプリとぶつかる PC のために、ショートカットの一覧の「組み合わせ」で **Ctrl＋Alt＋Win＋キー** に替えられる（設定 `hotKeyModifiers`、Windows だけ。替えたらすぐ登録し直し、画面の説明の文字も替わる）。
   - 二重には起動しない。2 つ目を起動したら、先に動いている方の操作ウィンドウを前に出して終わる（2 つ動くと、ショートカット・カメラ・Spout の名前を取り合うため）。
   - 描くキーは **Ctrl**（既定）/ Alt / Ctrl＋Alt から選ぶ。Alt は押して離すとメニューやリボンにフォーカスが移るので既定にしない。PowerToys の「マウスを見つける」（既定で Ctrl の 2 回押し）とぶつかるかは実機で確かめる。
6. **リポジトリ: このリポジトリの `windows/` フォルダ**
   - 仕様書・英語の訳（`Resources/en.lproj/Localizable.strings` を Windows 版からも直接読む）・キーボードの配列・アイコンを共有する。Mac の `build.sh` には影響させない。
   - `windows` ブランチで作り、区切りのよいところで main に入れる。リリースには Mac 版と Windows 版の zip を並べる。
7. **配布: 試作は署名なしの zip、公開版は Microsoft Store（MSIX）を第一候補**
   - 試作のうちは .NET を同梱した自己完結型の zip を GitHub のリリースに置く（SmartScreen の警告は「詳細情報 → 実行」で開ける）。
   - 公開版は Store にする（Store が署名し、警告が出ず、自動で更新される）。MSIX にするとパッケージの ID が付くので、あとで Windows の AI API を使うときにも都合がよい。

### あわせて決めておくこと

- 対応する Windows は **Windows 11** のみとする（録画から自分のウィンドウを外す指定や、画面の取り込みの枠を消す指定がそろうため）。
- GPU がない PC では、人物の切り抜きは Fast（MediaPipe を CPU で、1 コマ約 3 ms）にする。字幕のモデルの大きさは、字幕を作るときに速さを測ってから決める。

## 18. できあがりを確かめる項目

Mac 版で実際に確かめてきたことです。Windows 版でも同じことを確かめます。

- カメラを抜き差ししても、映像が止まったままにならない（3 秒で開き直す）
- カメラなしで起動しても、背景・字幕・手書きが全画面出力に出る
- ワイプが PowerPoint のスライドショーより手前に出続ける
- ワイプ・手書き（描いていないとき）・ホワイトボード・キーボード・指し棒・字幕の上をクリックすると、後ろのアプリに届く
- 全画面出力を外したら、ペン固定が外れて操作ウィンドウを操作できる
- 全画面出力を出している画面を外したら、全画面出力が閉じる（残った画面を覆わない）
- 全画面出力の上に描いた線が、プレビューにも同じ位置で出て、録画では 1 本だけ映る
- 画面を背景にしても合わせ鏡にならず、手書きとホワイトボードは背景に映る
- ホワイトボードが二重（板の上に板）にならない
- 録画に操作ウィンドウと録画停止ボタンが映らない
- 録画中にアプリを強制終了しても、それまでの録画が再生できる
- Bluetooth マイクで録画しても音が途切れない
- 字幕の .srt と字幕トラックの時刻が、録画の声と合っている
- 画面 1 台で、ワイプ・手書き・ホワイトボードだけで使える（[README の「画面 1 台で使うとき」](../README.md)）
